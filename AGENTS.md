# AGENTS.md

This file provides guidance to Codex (Codex.ai/code) when working with code in this repository.

## Project

**Arcades Profile** — personal site and portfolio. Next.js 15 (App Router) + React 19 + Payload CMS v3 (PostgreSQL) + Tailwind/SASS, deployed on Vercel. Postmark is the outbound email delivery layer for transactional mail, preview/test sends, and per-post newsletters. ActiveCampaign owns marketing contacts, audience lists, subscription state, and campaign/automation strategy. Vercel Blob stores media.

## Commands

```bash
npm run dev              # next dev → http://localhost:3000
npm run build            # next build
npm run lint             # next lint (ESLint)
npx tsc --noEmit         # typecheck (CI runs this; no npm script)
npm test                 # runs tsx --test against lib/, collections/, and mcp/ tests
npm run migrate          # apply Payload migrations
npm run check:migrations # CI guard: collection change without migration
npm run seed             # full seed (scripts/seed.ts)
npm run mcp              # MCP stdio server (mcp/payload-mcp.ts)
```

Run a single test file: `npx tsx --test lib/newsletter.test.ts`. The test runner is Node's built-in `node:test` via `tsx`; there is no Jest/Vitest.

Package manager is **npm only** — never `yarn`/`pnpm`/`bun`. Node 20 in CI.

## Architecture

### Next.js + Payload split via route groups

`app/` uses two route groups that do not affect URLs:

- `app/(frontend)/` — public site, RSS (`feed.xml`), all custom REST endpoints under `api/`, plus the MCP HTTP transport at `api/mcp/route.ts`.
- `app/(payload)/` — Payload admin UI at `/admin` and the auto-mounted Payload REST/GraphQL at `/api/[...slug]`. Do not put hand-written routes under this group; they will collide with Payload's catch-all.

### Payload CMS layer

`payload.config.ts` wires collections, the Lexical editor (with a custom `YouTubeBlock` from `blocks/`), the Vercel Blob storage adapter for media, and the Postmark-backed email adapter. ActiveCampaign is not an email delivery adapter here; it is the marketing/audience system. Collections (`collections/index.ts`): Users, Posts, PostReactions, PostmarkEvents, Groups, Books, Pages, Media, NavItems. Shared field builders are in `collections/fields/` (slug, tags, discoverability/meta), shared access/admin helpers in `collections/shared/`, and reusable lifecycle hooks in `collections/hooks/`.

Generated types live in `payload-types.ts` (regenerated by Payload — do not edit by hand). Import via the `@/payload-types` path alias; `@payload-config` resolves to `payload.config.ts`.

### Email ownership

Postmark sends email. Use `lib/postmark.ts` and the Payload Postmark adapter for outbound delivery, including auth messages, direct transactional sends, preview/test sends, and per-post newsletter delivery. If a message leaves this app, it should go through Postmark.

ActiveCampaign owns marketing. Use it for contacts, audience lists, subscription status, consent, segmentation, campaign strategy, and automations. Do not add new ActiveCampaign campaign/email sends for site newsletters or transactional app mail; resolve the audience from ActiveCampaign, then send through Postmark.

### Migrations are mandatory for schema changes

CI runs `npm run check:migrations` on PRs: if any file under `collections/` changes, the PR must add a new `migrations/YYYYMMDD_HHMMSS_*.ts` file or include `[skip-migration-check]` in a commit message (only valid for non-schema collection edits — admin labels, hooks, descriptions). Every migration exports both `up()` and `down()`; if rollback can't restore data, make `down()` a documented no-op rather than omitting it. Use `IF EXISTS`/`IF NOT EXISTS` guards. See `migrations/README.md`.

Vercel's build command runs `db:bootstrap` and `migrate` before `next build` when `DATABASE_URL` is set (see `vercel.json`).

### Post publishing pipeline

Posts have a `publish_status` of `draft | scheduled | published | sent`, a `suppressNewsletter` opt-out flag, and a read-only `newsletterSend` group that tracks Postmark delivery state.

1. **Draft → scheduled**: `promoteScheduledDraftHook` normalizes edited drafts with an explicit scheduled date to `publish_status: scheduled`; `validateScheduledPublishDateHook` then blocks scheduled posts whose date is already in the past.
2. **Scheduled → published/sent**: GitHub Actions workflow `.github/workflows/scheduled-posts.yml` hits `POST /api/posts/publish-scheduled` every 15 min with `Authorization: Bearer $CRON_SECRET`. `publishScheduledPosts` self-heals publish-queue dates, promotes due posts to `published`, writes a pending `newsletterSend` state, sends via Postmark, and flips `publish_status` to `sent` only after delivery succeeds.
3. **Audience and delivery split**: ActiveCampaign is the marketing/audience source of truth. `/api/subscribe` syncs contacts and list membership there, and per-post sends resolve active recipients from `AC_LIST_ID_{ALL,FICTION,ESSAYS}_PERPOST`. Postmark is the only mail delivery rail for Payload auth mail, transactional tests, preview sends, and per-post newsletter broadcasts. Do not add new ActiveCampaign campaign/email sends for site newsletters; use AC only for contacts, segmentation, consent, and marketing automation state.
4. **Delivery audit trail**: `lib/post-newsletter-delivery.ts` sends through `lib/postmark.ts`; accepted messages are recorded in the `postmark-events` collection, and `POST /api/postmark/webhook` updates aggregate delivery/open/click/bounce counts back onto `posts.newsletterSend`.
5. **Path revalidation**: `revalidatePathsFor` in `collections/hooks/revalidate.ts` invalidates the post URL plus group/project pages. The part index is computed from the post's position in its sorted group, not the raw `order` field.

`lib/post-url.ts` (`buildPostUrl`, `computePostPartIndex`) is the canonical URL builder — use it instead of constructing post paths inline.

### MCP server (dual transport)

The Payload MCP server lives in `mcp/`:

- `mcp/tools.ts` — tool definitions and handlers (shared)
- `mcp/payload-mcp.ts` — stdio entry point (`npm run mcp`, used by Codex via `.mcp.json`)
- `app/(frontend)/api/mcp/route.ts` — HTTP/SSE transport for Codex.ai custom connectors

Two key scopes: write keys (`MCP_API_KEY` / `MCP_API_KEYS`) authorize any tool; read keys (`MCP_READ_KEY` / `MCP_READ_KEYS`) authorize only `list_*`/`get_*`. The `*_KEYS` plural variants accept comma-separated lists for rotation. `MCP_API_KEY` is distinct from `PAYLOAD_API_KEY` — rotate independently.

When adding a tool, register it in `mcp/tools.ts` so both transports pick it up; don't add it to the route handler directly.

### Env & secrets

All env vars are documented in `.env.example`. The repo loads `.env.local` in dev. `SITE_TZ` controls site-local publish queue labels and preview timestamps, defaulting to `America/Chicago`. `lib/env.ts` exposes `getDatabaseURLForPayloadConfig({ requireDatabaseURL })` and `getPayloadSecret()` — `payload.config.ts` only requires `DATABASE_URL` when running a migrate subcommand, so dev boots even without a DB configured. Both `DATABASE_URL` and `DATABASE_URI` are accepted.

Never commit `.env*`. CI runs TruffleHog on PR diffs.

### Syncing env vars to Vercel

```bash
vercel env add VAR_NAME production --value "$VALUE" --yes
vercel env add VAR_NAME development --value "$VALUE" --yes
```

`preview` is broken in Vercel CLI 53.1.0 (`git_branch_required` even with no branch). Workaround:

```bash
# Vercel CLI stores auth.json under an OS-specific config dir.
case "$(uname -s)" in
  Darwin) AUTH="$HOME/Library/Application Support/com.vercel.cli/auth.json" ;;
  Linux)  AUTH="${XDG_CONFIG_HOME:-$HOME/.config}/com.vercel.cli/auth.json" ;;
  *)      AUTH="${VERCEL_AUTH_JSON:?set VERCEL_AUTH_JSON to your auth.json path}" ;;
esac
TOKEN=$(jq -r '.token' "$AUTH")
ORG=$(jq -r '.orgId' .vercel/project.json)
PROJ=$(jq -r '.projectId' .vercel/project.json)
curl -sS -X POST "https://api.vercel.com/v10/projects/$PROJ/env?teamId=$ORG" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d "{\"key\":\"VAR_NAME\",\"value\":\"$VALUE\",\"type\":\"plain\",\"target\":[\"preview\"]}"
```

Verify with `vercel env ls`. Drop the API workaround once CLI > 53.1.0.

## Conventions

- **Scope discipline**: one feature → one PR. If a request bundles independent features, ask which to tackle first. Capture mid-task ideas as GitHub issues rather than expanding the current PR.
- **Commit messages**: short imperative subject (≤72 chars), no body unless genuinely non-obvious.
- TypeScript strict mode is on — avoid `any`.
- Path aliases: `@/*` → repo root, `@payload-config` → `payload.config.ts`.
- New REST routes go under `app/(frontend)/api/`, never `app/(payload)/api/` (that's Payload's catch-all).
- Cron-style endpoints authenticate with `Authorization: Bearer $CRON_SECRET` via `lib/cronAuth.ts`.
