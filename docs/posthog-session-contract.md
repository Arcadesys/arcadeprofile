# Sitewide PostHog session contract

The proposed engagement/conversion extension is documented in [engagement and conversions](engagement-and-conversions.md); its versioned estimates and additional request stages take effect only after an approved release.

The sitewide HTTP collector sends UUIDv7 `$session_id` values. PostHog requires UUIDv7 for custom sessions and a maximum 24-hour lifetime ([custom session IDs](https://posthog.com/docs/data/sessions#custom-session-ids)). The existing UUIDv4 `arcade-posthog-anonymous-id` visitor identity remains unchanged, independent of other sites. No identify, alias, replay, fingerprinting or cross-site joining is added.

`arcade-posthog-session-v2` stores `{version:2,id,startedAt,lastActivityAt}` in tab-local session storage. IDs encode creation time and rotate on the first permitted event after 30 minutes without a captured event, at 24 hours, on invalid state or on clock rollback. Passive reading is not activity for this timer. Session state is updated only by existing allowlisted events. The tab's separate UUIDv4 `arcade-posthog-window-id` survives session rotations. Entry page/referrer/campaign attribution resets with a new session. Unavailable storage uses in-memory session state for the page lifetime; visitor fallback remains ephemeral as before.

Within a page, the latest tab-memory session is authoritative after the first captured event. Session storage initializes a new page/reload and is updated best-effort; a readable old record cannot replace newer memory when writes fail because of quota or read-only storage. Idle and maximum-duration checks still apply to memory, without any cross-tab sharing.

Existing UUIDv4 session storage is ignored by the new client. The receiver continues accepting legacy UUIDv4 session/window receipts during rollout and preserves raw visitor IDs, event names, production hostname and historical events. It derives `session_model=tab_uuidv7_v2` for UUIDv7 receipts and `legacy_v1` otherwise. Do not rewrite or backfill historical events. Rolling back the client leaves the old key available and legacy receipts still accepted.

Historical main/hack UUIDv4 sessions did not populate native session reports. Their pageviews and raw session IDs remain historical observations, but native session counts, duration and bounce before/after this boundary are not directly comparable. Work already uses SDK-managed UUIDv7 sessions and has session-storage-only identity: do not combine its visitor counts with the creative site's persistent visitor identity. Record the actual production cutover time after release; a PR or successful build is not live verification.

## Bounded receipts (pending release)

`collection_version=bounded_receipts_v1` marks the additive collection contract; it is not evidence of deployment. A public visit has one `$pageview` and at most one terminal `$pageleave` on navigation, unmount or pagehide, linked by an ephemeral `$pageview_id`. Strict Mode cleanup and repeated pagehide do not duplicate the visit. BFCache restoration starts a fresh pageview/leave pair, retaining the normal tab-session rules. Same-path query/hash changes add no view. The leave freezes the original sanitized page/session, including navigation onto an excluded route; that excluded route is never collected.

`$prev_pageview_duration` is monotonic elapsed seconds for that visit; `visible_seconds` separately excludes hidden time. Neither is active attention or reading. No visibility heartbeat or focus/key/coordinate log is added. Visibility only pauses/resumes the local visible-time estimate. Clock rollback, visits at least 30 minutes old, or an expired 24-hour session suppress the leave. Mobile termination and blocked transport can lose receipts. Broad autocapture remains **disabled**: native bounce can still classify a quick custom CTA action as a bounce, and native session duration includes hidden time between events. Do not present either as a validated engagement outcome. Use the existing bounded reader estimates and intent receipts separately. [Pageleave guidance](https://posthog.com/docs/health-checks/pageleave-events), [previous pageview duration](https://posthog.com/tutorials/time-on-page).

The receiver derives coarse `$device_type=Desktop|Mobile|Tablet` from the already available HTTP user agent; missing, unrecognized and bot/automation agents leave it absent. These are approximate UA categories (desktop-mode tablets can look like desktops), not device identification. Sanitized first-entry `$referrer` also populates native `$referring_domain`, alongside the old `referring_domain`. Existing structurally allowlisted `utm_*` tokens remain frozen with entry context through internal routes, even when sessionStorage is blocked. Missing source stays absent, never invented as Direct. No `$set`, `$set_once`, identify, person `$initial_*`, persistent identity expansion or cross-host joining is added. Native **person** “Initial” attribution remains absent by design; report event/session entry fields. [UTM event/session versus person properties](https://posthog.com/docs/data/utm-segmentation).

Every new transport receipt has a UUIDv4 `uuid` and exact ISO `timestamp`, frozen with its sanitized body before sending. Invalid/partial tuples and timestamps more than five minutes from receiver time fail closed; legacy clients without the tuple remain accepted. Each tab holds at most 32 pending receipts in memory, with keepalive POSTs, a five-second attempt timeout, and at most three attempts on network failure/408/429/5xx (250ms then 1s backoff). Pagehide flushes pending work but never duplicates an in-flight attempt. Success/other 4xx stops retries. No beacon blind resend, disk queue, navigation delay or new cookie is used. Browser DNT and receiver DNT suppress transport; queued work is dropped if DNT is enabled.

The receiver coalesces in-flight/successful identical UUIDs within one instance for two minutes, bounded to 512 hashed receipt entries, and rejects UUID reuse with a changed sanitized body. Failures can retry. Cross-instance/restart, cache saturation, or ambiguous upstream failures still rely on PostHog's **eventual** deduplication of the unchanged UUID/event/timestamp/distinct-id tuple; immediate exactly-once ingestion is not guaranteed. For delivery diagnostics count distinct receipt UUIDs, and allow ingestion to settle before comparing raw counts. [Provider deduplication contract](https://posthog.com/docs/data-pipelines/troubleshooting).

`end-reached` does not prove finished reading; `resume-click` means resume reading, not résumé navigation. Subscription request acceptance does not prove confirmed subscription. MFF has a separate overlapping stream: never sum its pageviews with sitewide pageviews. The raw canonical production host remains `www.thearcades.me`; historical host filters should explicitly include verified aliases where applicable. Historical sparse-collection bounce is not comparable to the new lifecycle stream, and this PR does not backfill it.

## Verification after an approved release

1. Record deployed commit and UTC cutover time. Open a known public essay and navigate to another public page in the same tab, using no personal query values.
2. Confirm one sitewide pageview per intended pathname transition, a stable visitor ID and UUIDv7 session ID, separate window ID, safe reconstructed URL, and `session_model=tab_uuidv7_v2`. Confirm native session receipt after ingestion settles; inspect saved/rendered reports separately.
3. Verify existing public reader and onward-reading actions retain their names. Use mocked signup responses for acceptance-stage tests; do not send email or submit a live signup for this smoke test.
4. Check no capture on verification/unsubscribe/private/unknown paths or preview hosts. Confirm blocked storage/analytics leaves navigation usable. Do not export raw visitor IDs or payloads in release evidence.
5. Compare complete UTC periods by hostname and collection version, preserving the pre-release raw-event baseline. Do not claim improved engagement from the session coverage correction alone.
6. After separately approved deployment, verify new UUID/timestamp receipts, lifecycle pairs, coarse device and entry referrer/UTMs through outgoing payload, receiver acknowledgment, provider receipt and session materialization. Local intercepted tests/PR CI do not establish production receipt. Never submit a real signup or purchase for QA.
